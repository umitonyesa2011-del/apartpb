# Дороги СПб — карта дорожных ремонтов по данным госзакупок

Сайт показывает на карте Санкт-Петербурга улицы, где идёт, планируется или уже завершён
ремонт дорог. Данные берутся из ЕИС (zakupki.gov.ru) по 44-ФЗ. По клику на дорогу
открывается карточка: **подрядчик, дата начала, дата завершения, краткое описание работ**,
сумма контракта и ссылка на закупку. Под каждым объектом — **чат**, куда жители могут
скидывать фотографии и подписи о том, как идут работы.

## Что внутри

```
roads/
├── index.html                интерфейс: карта + список + карточка + чат
├── assets/css/styles.css     тёмная тема, адаптив
├── assets/js/api.js          слой данных: сервер или localStorage
├── assets/js/app.js          карта Leaflet, фильтры, карточка, чат
├── data/objects.json         ← объекты ремонта (сюда пишет парсер)
├── parser/fetch_zakupki.py   сбор данных из ЕИС + геометрия улиц из OSM
└── server/server.js          backend общего чата (Node.js, без зависимостей)
```

## Как запустить

### Вариант 1. С общим чатом (рекомендуется)

```bash
cd roads
node server/server.js          # http://localhost:8080
PORT=3000 node server/server.js
```

Сервер отдаёт сайт и хранит чат: сообщения — в `server/data/chat.json`,
фотографии — в `server/uploads/`. Всё, что написали посетители, видно всем.
Зависимостей нет, нужен только Node.js 18+.

### Вариант 2. Только статика (GitHub Pages, Netlify, `python3 -m http.server`)

```bash
cd roads && python3 -m http.server 8000
```

Карта, фильтры и карточки работают полностью. Backend'а нет, поэтому чат переходит
в **локальный режим**: сообщения и фото сохраняются в `localStorage` браузера и видны
только этому посетителю. В шапке справа всегда написано, какой режим сейчас активен.

## Как обновить данные из ЕИС

```bash
cd roads
python3 parser/fetch_zakupki.py                 # 2 страницы выдачи, до 40 объектов
python3 parser/fetch_zakupki.py --pages 5 --limit 100
python3 parser/fetch_zakupki.py --no-geo        # без обращения к OpenStreetMap
python3 parser/fetch_zakupki.py --query "ремонт тротуаров" --query "ямочный ремонт"
```

Скрипт (только стандартная библиотека Python 3.8+):

1. запрашивает RSS-выдачу поиска ЕИС по 44-ФЗ с фильтром «место поставки — Санкт-Петербург»;
2. по номеру закупки ищет заключённый контракт → подрядчик и сроки исполнения;
3. вытаскивает название улицы из наименования закупки;
4. берёт геометрию улицы из OpenStreetMap через Overpass API (кэш — `parser/cache/geo.json`);
5. перезаписывает `data/objects.json`.

Ключи: `--pages`, `--limit`, `--query`, `--out`, `--no-geo`, `--no-contracts`, `--keep-empty`.

**О чём стоит знать:** ЕИС меняет вёрстку и ограничивает частоту запросов, поэтому парсер
написан «мягко» — не разобранное поле остаётся пустым, объект всё равно попадает в выдачу,
а все проблемы печатаются в консоль. Объекты, для которых не нашлась геометрия улицы,
по умолчанию отбрасываются (`--keep-empty` оставляет их). Overpass опрашивается не чаще
раза в секунду.

## Формат `data/objects.json`

```jsonc
{
  "source": "eis",              // "demo" — показывается предупреждение в шапке
  "generatedAt": "2026-08-20T09:00:00+03:00",
  "items": [{
    "id": "0172200002526000411", // номер закупки, он же ключ чата (только цифры/латиница)
    "street": "Невский проспект",
    "section": "от Садовой улицы до площади Восстания",
    "district": "Центральный",
    "customer": "СПб ГКУ «Дирекция дорожного хозяйства»",
    "contractor": "ООО «Дорстрой-Нева»",
    "contractorInn": "7801000101",
    "price": 248500000,
    "dateStart": "2026-06-01",
    "dateEnd": "2026-09-15",
    "status": "in_progress",     // in_progress | planned | done
    "work": "Капитальный ремонт",
    "description": "Что именно делают на объекте",
    "source": "https://zakupki.gov.ru/…",
    "geometry": [[59.9337, 30.3269], [59.931, 30.3606]]
  }]
}
```

`geometry` — либо одна ломаная `[[lat, lng], …]`, либо несколько
`[[[lat, lng], …], …]` (улица из OSM обычно состоит из нескольких кусков).

## Что сейчас в репозитории

`data/objects.json` содержит **демонстрационный набор из 16 объектов**: названия подрядчиков
вымышлены, геометрия улиц дана приближённо. Пока в файле стоит `"source": "demo"`,
в шапке сайта висит предупреждение. После запуска парсера оно исчезнет.

## API сервера

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/health` | проверка, что backend жив |
| GET | `/api/objects` | содержимое `data/objects.json` |
| GET | `/api/chat-counts` | `{ "<id объекта>": количество сообщений }` |
| GET | `/api/chat/<id>` | сообщения объекта |
| POST | `/api/chat/<id>` | `{ author, text, photo }`, фото — dataURL |
| GET | `/uploads/<файл>` | загруженная фотография |

Ограничения: тело запроса ≤ 8 МБ, фото ≤ 6 МБ (JPEG/PNG/WebP), текст ≤ 1000 символов,
имя ≤ 40 символов, не более 30 сообщений с одного IP за 10 минут. Фото дополнительно
сжимается в браузере до 1600 px по длинной стороне.

Модерации в чате нет — если сайт открыт наружу, поставьте его за reverse-proxy
и добавьте свою проверку сообщений.

## Что можно доработать

- админку для правки объектов и удаления сообщений;
- привязку фотографий к геопозиции съёмки;
- уведомления о новых сообщениях по интересующим улицам;
- историю: сколько раз одну и ту же улицу ремонтировали за последние годы.
